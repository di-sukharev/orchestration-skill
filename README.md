# orchestration-skill

Лид доводит задачу до полной, минимально достаточной реализации через саб-агентов.
Проектные файлы и истории саб-агентов не читает; держит контекст требований,
решений и доказательств. Всех саб-агентов запускает напрямую, без вложенной делегации.

Реализующий саб-агент исследует задачу и предлагает план на уровне идеи,
edge cases и проверки. Лид задаёт открытые вопросы только при существенной
неопределённости. Затем тот же саб-агент реализует всю задачу, по одной подзадаче,
без промежуточных согласований, и возвращает отчёт с результатами и доказательствами.

Каждый раунд ревью ведёт свежий проверяющий саб-агент. Он получает исходные требования,
проверяет все изменения и затронутые зависимости, сообщает конкретные дефекты,
воспроизведение, нужные тесты и минимальные исправления. Лид принимает замечания,
тот же саб-агент исправляет; следующий независимо проверяет обновлённый результат.

Быстрые проверки выполняются до передачи результата, остальные обязательные —
перед завершением. Готово, когда принятые замечания и существенные пробелы ревью
закрыты, проверки прошли. Препятствия решаются внутри задачи; остановка — только
когда нужно действие человека. Визуальная проверка — пользователю.
Полный протокол: [SKILL.md](orchestration/SKILL.md).

## Установка

Отправьте агенту:

```text
Install this skill globally: https://github.com/di-sukharev/orchestration-skill
```

Или скопируйте `orchestration` в `~/.codex/skills/` либо `~/.claude/skills/`.
Нужна среда с саб-агентами; другие скиллы не требуются.

## Использование

```text
$orchestration
Implement X through subagents. Use gpt-5.6-luna for all subagents.
```

В Claude Code — `/orchestration`. Модель лида сохраняется.
Единая модель всех саб-агентов задаётся обычным текстом.
По умолчанию — `gpt-5.6-luna` в Codex, `sonnet` в Claude Code.
Недоступная модель не подменяется молча.

Коммиты, push и деплой — по запросу пользователя.
