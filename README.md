# orchestration-skill

Лид доводит задачу до абсолютно достаточной реализации: все требования выполнены,
ничего лишнего, UX/UI минимален. Цель — минимум времени и токенов, включая переделки.

Саб-агенты исследуют и пишут код. Лид выдаёт небольшие подзадачи по одной с точным
definition of done и принимает результат по коротким отчётам с доказательствами.
Обычно работает тот же исполнитель; смена — по решению лида. Историю саб-агентов
лид не читает, код смотрит, когда так быстрее или надёжнее.

Свежий ревьюер проверяет все изменения задачи на существенные дефекты и проблемы
DX, сообщает доказательства, пробелы проверки и оценку готовности 1–10. Лид решает,
что чинить; тот же ревьюер исправляет, новый проверяет заново. Визуальная проверка —
за пользователем.

Рутинные проверки — после ревью, точечные допустимы раньше. При падении: root cause
с доказательствами → решение лида → исправление тем же сабом → новое ревью → повтор
проверок. Готово, когда принятые замечания закрыты, существенных пробелов ревью нет
и проверки прошли. Полный протокол — в [SKILL.md](orchestration/SKILL.md).

## Установка

Отправьте агенту:

```text
Install this skill globally: https://github.com/di-sukharev/orchestration-skill
```

Или скопируйте `orchestration` в `~/.codex/skills/` либо `~/.claude/skills/`.
Нужна среда с саб-агентами и выбранными моделями; другие скиллы не нужны.

## Использование

```text
$orchestration
Implement X. First create a plan, then execute it through subagents.
```

В Claude Code — `/orchestration`. Только план: добавьте `Do not change code yet`.

Модель лида сохраняется. Сабы по умолчанию: `gpt-5.6-luna` в Codex, `sonnet` в
Claude Code. Другие модели задаются обычным текстом, например:

```text
Use Sonnet for implementation and Opus for review.
```

Коммиты, push и деплой — по запросу пользователя.
