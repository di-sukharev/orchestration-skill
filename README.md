# orchestration-skill

Главная модель — лид, саб-агенты — исполнители. По умолчанию это Luna в Codex
и Sonnet в Claude Code. Цель — абсолютно достаточная реализация за минимум времени
и токенов. Решения — минимально достаточные, без лишней работы.
Все acceptance criteria должны быть выполнены. UX/UI — максимально простой
в рамках требований; необязательные улучшения пользователь запросит отдельно.

Исполнитель находит нужный код и приносит короткий отчёт. Лид сохраняет контекст
для требований и решений; сам читает код, когда так быстрее или надёжнее.
Он разбивает задачу на небольшие подзадачи и обычно выдаёт их одному исполнителю
по очереди, с точным definition of done. Следующая — когда предыдущая закрыта,
что исполнитель подтверждает отчётом с доказательствами и оставшимися вопросами.
Размер подзадач и смена исполнителя — на усмотрение лида. Историю саб-агентов
лид не читает.

Каждый проход ревью выполняет новый агент. Он проверяет все изменения задачи,
продолжает после первой находки и отмечает существенные пробелы проверки.
Уже в первом отчёте он объясняет условия сбоя, затронутое требование, существующие
защиты и последствия, указывает код и предлагает минимальное исправление с его
эффектами и, где полезно, сценарий
регрессионного теста. Замечания требуют конкретных доказательств; намеренные
изменения считаются дефектами, только если нарушают требования. Оценка готовности
1–10 — ориентир для лида. Лид оценивает доказательства, при необходимости задаёт
открытые уточняющие вопросы и решает, что исправлять и где исправление избыточно.
Тот же ревьюер исправляет принятые замечания, затем новый агент проверяет все
изменения задачи. Ревью ищет существенные ошибки и проблемы DX; визуальную проверку
выполняет пользователь.

Рутинные тесты и проверки отложены до чистого ревью. Точечные проверки допустимы
раньше, если нужны для подтверждения ошибки или исправления. Если проверка падает,
саб-агент сначала приносит root cause с доказательствами; после оценки лида тот же
агент исправляет причину. Затем — новое ревью всех изменений задачи и повтор нужных
проверок. Готово, когда принятые замечания исправлены, существенных пробелов ревью
нет и необходимые проверки прошли.

## Установка

Отправьте агенту:

```text
Install this skill globally: https://github.com/di-sukharev/orchestration-skill
```

Или скопируйте папку `orchestration` в `~/.codex/skills/`
(для Claude Code — `~/.claude/skills/`). Другие скиллы не нужны.

## Использование

В Codex:

```text
$orchestration
Implement X. First create a plan, then execute it through subagents.
```

В Claude Code:

```text
/orchestration Implement X. First create a plan, then execute it through subagents.
```

Другую модель можно указать обычной фразой в запросе:

```text
Use GPT-6 Astra for subagents.
```

```text
Use Sonnet for implementation and Opus for review.
```

Если модель не указана, саб-агенты используют `gpt-5.6-luna` в Codex
и `sonnet` в Claude Code. Модель самого лида сохраняется.

Для одного плана добавьте: «Do not change code yet». Нужна среда с поддержкой
саб-агентов и выбранной модели. Скилл не даёт отдельного разрешения на коммиты,
push или деплой.
