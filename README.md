# orchestration-skill

`orchestration` — скилл для разработки, где главная модель работает как лид,
а Luna выполняют первичный поиск, пишут код и проводят независимые ревью.

Лид получает краткий JSON с картой кода, сам изучает нужные реализации,
составляет план и разбивает работу на очень мелкие подзадачи. Он даёт их строго
по одной одному и тому же Luna-исполнителю: так тот сохраняет знакомство с кодом.
Для каждой подзадачи лид точно формулирует Definition of Done — ожидаемый
результат, границы, важные углы и проверки. Следующая подзадача начинается после
проверки результата предыдущей.

Лид объясняет идею реализации, но код пишет исполнитель. Историю и контекст
саб-агентов лид не читает: получает только короткий JSON или такой же краткий
отчёт по Definition of Done. Если нужен свежий взгляд без прежних предположений,
лид может заменить исполнителя новым агентом без контекста.

На каждый проход ревью запускается новый Luna-агент без истории диалога. Сначала
он только проверяет все изменения задачи и возвращает проблемы с доказательствами.
Лид решает, что дополнительно проверить и что исправить; после его согласия
этот же ревьюер вносит правки. Затем приходит следующий независимый ревьюер.
Цикл завершается чистым ревью и успешными проверками.

## Установка

Отправьте агенту:

```text
Установи этот скилл глобально: https://github.com/di-sukharev/orchestration-skill
```

Для ручной установки скопируйте папку `orchestration` из этого репозитория
в каталог скиллов вашего агента. Например, из корня репозитория для Codex:

```sh
mkdir -p ~/.codex/skills
cp -R orchestration ~/.codex/skills/
```

Для Claude Code каталог назначения — `~/.claude/skills/`. Сам процесс требует
среду с саб-агентами и возможностью выбрать нужную модель. Если Luna недоступна,
агент сообщит об этом и остановится, не подменяя её молча.

## Использование

```text
$orchestration
Реализуй Х. Сначала составь план, затем выполни его через саб-агентов.
```

Замените Х конкретной доработкой и опишите ожидаемый результат. Главная модель
остаётся моделью текущего диалога. Для поиска, реализации и каждого ревью по
умолчанию используется `gpt-5.6-luna`; другую модель можно указать явно в запросе.
Скилл передаёт выбор инструменту запуска саб-агентов.

Если пока нужен только план:

```text
$orchestration
Составь только план реализации Х. Код пока не меняй.
```

Скилл не требует `loop-tasks` или `loop-code-review`. В отличие от выполнения
готовой очереди задач, лид здесь участвует в исследовании и планировании.
Согласованные с лидом замечания исправляет нашедший их ревьюер, а следующий
проверяет весь результат заново. Коммиты, push и деплой не выполняются без
разрешения пользователя.

Оценка ревьюера не заменяет тесты и проверку продукта человеком. Если обязательные
проверки недоступны или цикл перестал продвигаться, агент сообщает о блокере,
а не объявляет результат готовым.
